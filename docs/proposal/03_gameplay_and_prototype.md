# 03. ゲームプレイ設計とプロトタイプ開発計画

## 1. 『戦場のヴァルキュリア』×『バイオハザード』の融合コンセプト

2D・1人称視点（2.5D）の強みを最大限に活かすゲームプレイの方向性として、2つの作品の良さを掛け合わせた**「戦術的サバイバル1人称アクション」**を提案します。

### 取り入れる要素と2Dでの実装

1. **移動と遮蔽の緊張感（ヴァルキュリア要素）**
   - 戦場には腰高の遮蔽物（土嚢・バリケード）や建物の角を配置。
   - **しゃがみ／カバー操作**: 遮蔽物の後ろでしゃがむと敵の射線（LoS）が切れ、立ち上がって覗き込むと撃てる（画面のカメラ高さ・水平線を上下させるだけで1人称のしゃがみ・覗き込みを完全表現）。
   - **迎撃とリソース**: 敵の視界内（正面〜斜め前のコーン範囲）を無防備に横切ると敵が即座に「構え」→「発砲」の予備動作に入り、移動しながらの回避や遮蔽への駆け込みが求められる。
   - 任意で**「リアルタイム制」**（バイオハザード寄り）にも**「AP消費のアクション＋ターン/アクティブ切り替え制」**（ヴァルキュリア寄り）にも設計可能。

2. **1人称の没入感・資源管理・部位狙い（バイオハザード要素）**
   - **手元UI（1人称の武器スプライト）**: 画面下部にプレイヤーの武器・腕を2Dスプライト（数枚：構え・発砲・リロード・近接ナイフ等）で表示し、移動時の手ブレ（ボビング）を入れるだけで一気に1人称の没入感が出る。
   - **残弾管理とリロードの隙**: 弾数が限られており、リロード中は移動速度が落ちる／撃てない。
   - **弱点部位狙い**: 敵の「頭」を狙えば大ダメージ、「脚」を狙えば怯み（膝つき絵）で接近を遅らせる、「盾」に当たれば弾かれる、といった駆け引き。

3. **2D手描きアートならではの演出**
   - 戦場全体を水彩画・ペン画・劇画調などで統一し、カメラの周囲にわずかな紙テクスチャやビネット（周辺減光）を乗せることで、「3Dの劣化版」ではなく**「動くイラストの中を1人称で歩く唯一無二の体験」**に昇華できます。

## 2. 推奨技術スタック（3Dエンジン不使用・純2D構成）

本構想は処理が非常に軽いため、どの2D環境でも構築可能です。

| 選択肢 | 特徴 | 向いているケース |
| :--- | :--- | :--- |
| **Web (TypeScript + HTML5 Canvas / PixiJS)** | ブラウザで即起動・配布が容易。2Dレイキャストやスプライト描画が数百行で書ける | 最速でプロトタイプを触って検証したい場合（**最推奨**） |
| **Godot Engine (2Dノードのみ)** | 2Dのノード・アニメーション・UI・サウンド管理が強力。配布ビルドも簡単 | 本格的なゲーム制作・ステージ量産を見据える場合 |
| **Pygame / Love2D (Lua)** | コードベースでシンプルに2.5Dレンダラを組める | 軽量な実験・アルゴリズム検証をしたい場合 |

## 3. 最小プロトタイプ（MVP）検証ロードマップ

いきなり20枚の絵を何体も描く前に、**仮絵（シルエットや色違いの棒人間／図形）**を使って「3Dのように遊べる手触り」を最短で検証するステップを推奨します。

### Phase 1：2.5D空間と移動・旋回の検証（目安：1〜2日）
- 2Dグリッドマップ（壁・遮蔽物・通路）を作成し、レイキャストで壁と床を描画。
- WASD移動（前後＋ストレイフ）とマウス/左右キーによる滑らかな視点旋回、しゃがみ（カメラ高さ変更）を実装。
- **確認ポイント**: 「3Dを使わずに、廊下を歩いたり角から覗いたりする感覚が出るか？」

### Phase 2：ビルボードユニットと20枚アニメーション検証（目安：2〜3日）
- 1体のテストユニット（まずは仮絵で正面・斜め・横・背面・歩行・攻撃・怯み・ダウンの計20枚相当）を配置。
- カメラ角度に応じたスプライト自動切り替え＋左右反転＋歩行ボビング＋被弾フラッシュを実装。
- **確認ポイント**: 「敵の周りを回り込んだり、敵がこちらに近づいてきたりしたとき、紙芝居にならず立体的に見えるか？」

### Phase 3：1人称コンバットと部位判定の検証（目安：2〜3日）
- プレイヤーのエイム（画面中央レティクル）、射撃、リロード、敵の部位（頭・胴・脚）判定を実装。
- 敵AI（索敵→構え予備動作→射撃／接近）と遮蔽物による射線遮断を実装。
- **確認ポイント**: 「遮蔽物に隠れてタイミングを見て撃つ」「頭や脚を狙って戦う」ゲームプレイが面白いか？

## 4. リスクと対策まとめ

- **リスク1：上下の空間移動（2階建て・階段・坂道）が表現しにくい**
  - **対策**: ステージは基本「1フロア＋高さの異なる遮蔽物（低い壁・高い壁）」で構成し、階層移動は階段アイコン／エリア切り替えで処理する（初期『DOOM』以前の構造）。これにより2Dロジックの単純さを維持できる。
- **リスク2：極端に近づいたときに2D絵のドットや粗さが目立つ**
  - **対策**: ユニット画像は高解像度（例：高さ512px〜1024px）で描き、敵が一定距離以内に密着しないようAIと押し戻し（2D円形コリジョン）を設定する。
- **リスク3：絵の枚数不足で動きが硬く見える**
  - **対策**: 02章で挙げた「歩行ボビング」「発砲時の一瞬の拡大」「接地影」「別レイヤーの銃口閃光・ヒットエフェクト」を必ずセットで実装する。
