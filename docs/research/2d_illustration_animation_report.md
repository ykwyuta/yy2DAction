# 2次元イラストのアニメーション表現手法・ライセンス・特許 事前調査報告書

**作成日:** 2026年11月13日  
**調査目的:** 2次元イラストを活用したゲームを、既存の商用ソフトウェアやプロプライエタリなランタイムに極力依存せず、独自に開発・商用利用するための技術選定および知財（ライセンス・特許）リスクの事前調査。

---

## 1. エグゼクティブサマリー（調査結論）

1. **既存商用ソフトに依存しない独自開発は十分に可能**
   - 2Dイラストを動かす基盤技術のうち、**「2Dボーン（骨格）スキニング」「自由形状変形（FFD）／ARAP変形」「スプライト切り替え＋シェーダーによるプロシージャル揺れ」**などは学術論文やCGの基礎技術として広く公知であり、特許・ロイヤリティの制約なく独自実装（またはMIT/BSD系OSSの活用）が可能です。
2. **注意すべき最大のリスクは「Live2D方式の模倣」**
   - 株式会社Live2Dは、2Dイラストをメッシュ分割しデフォーマとパラメータ連動で立体的に動かすコア技術について複数の特許（特許第5505848号、特許第6663066号など）を保有しています。Live2Dの仕組み（ワープデフォーマ階層＋パラメータ補間）やデータ形式（`.moc3`等）を模倣した独自ランタイム／ツールを開発・公開することは特許侵害や規約違反のリスクが高いため避けるべきです。
3. **本プロジェクト（2D・1人称アクション／戦術ゲーム）への推奨**
   - 今回のプロトタイプで検証した**「約20枚のスプライト切り替え」**をベースにしつつ、**「頂点シェーダーによる呼吸・髪・コートの揺れ」**や**「簡易2Dボーン（腕・武器の追従）」**を独自実装で組み合わせる構成が、開発コスト・表現力・知財安全性のバランスに最も優れています。

## 2. 2次元イラストを動かす主要手法と技術的特徴

| 手法カテゴリ | 技術的仕組み | 得意な表現 | 苦手な表現・課題 |
| :--- | :--- | :--- | :--- |
| **① 2Dボーン（骨格）スキニング**<br>（Spine / DragonBones / 自作） | パーツ分けしたイラストに三角形メッシュを割り当て、階層ボーンの回転・移動に合わせて頂点をLBS（Linear Blend Skinning）等で変形。 | 手足の関節曲げ、歩行、武器アクション、物理演算による髪・布の揺れ。 | 顔を左右に大きく振り向かせるような「立体的な回り込み」表現。 |
| **② パラメータ連動メッシュ変形**<br>（Live2D / Inochi2D） | アートメッシュに対し格子状の変形枠（デフォーマ）を多段に組み、パラメータ値（角度X/Y、口開閉など）に応じたキー形状間をリアルタイム補間。 | 1枚の立ち絵ベースで顔を3Dのように立体回転させる表現、視線追従、会話シーン。 | Live2Dは特許で保護されている領域が広い。またパーツ分け・モデリング工数が非常に重い。 |
| **③ ケージ変形・ARAP変形**<br>（学術アルゴリズムベース） | 周囲の制御ケージ（Mean Value Coordinates等）や、局所剛性を保つ最適化（As-Rigid-As-Possible変形）で、数点のハンドル操作から自然にメッシュを変形。 | 体のしなり、柔らかな潰れ・伸び（スクワッシュ＆ストレッチ）、直感的なポーズ付け。 | 計算負荷がLBSよりやや高い（ただし2Dキャラクター数体〜十数体程度なら現代のPC/スマホで十分リアルタイム動作）。 |
| **④ ベクターモーフィング**<br>（Rive / Lottie系） | ラスター画像ではなくベクターパス（曲線）や塗りを直接補間し、ステートマシンで状態遷移を制御。 | UI、アイコン、フラット／アニメ調のシャープなキャラクター。 | 水彩画・厚塗り・手描き筆致などの複雑なラスターイラストの表現には不向き。 |
| **⑤ コマ切り替え＋プロシージャル演出**<br>（古典2.5D＋シェーダー強化） | 用意した複数枚の完成絵（例：20枚）を角度・状態で切り替え、2D座標・拡縮・傾き・頂点シェーダー（風揺れ・呼吸）をプログラムで加算。 | 背面・斜め・ダウン等の**劇的な角度変化や別ポーズ**。画風・タッチを100%維持できる。 | 中割り枚数が少ない場合、適切な補間演出（ボビング・フラッシュ・エフェクト分離）を入れないと硬く見える。 |
| **⑥ AI動画生成・ニューラルリギング**<br>（LivePortrait等） | 1枚の静止画からディープラーニングモデルで顔・体の動きを推論生成。 | 静止画1枚からのテスト動画生成、プリレンダリング映像素材の量産。 | リアルタイムゲームへの組み込みはGPU負荷・遅延・モデルの商用ライセンス制限（研究用のみ等）・画風崩れが課題。 |

## 4. 特許および知的財産権に関する詳細調査

既存ソフトに依存せず独自に2Dイラストアニメーションの仕組みを実装する場合、**特許権のクリアランス**が最重要となります。

### 4.1 Live2D社の保有特許とリスク範囲
株式会社Live2D（旧・株式会社サイバーノイズ）は、2Dイラストを立体的に動かす技術に関して日本国内外で複数の特許を保有しています。
- **代表例1：特許第5505848号**（特開2009-104570 関連）
  - **概要**: 2D原画の複数パーツやメッシュを連動させ、絵のタッチを保ったまま立体的な変形・アニメーション・視線追従等をリアルタイムに行う基礎技術群。
  - **存続期間**: 出願日（2007年頃）から原則20年（年金納付による維持が前提）。※2026年現在、一部基礎特許は存続期間満了が近づいていますが、関連する周辺特許や後続特許が多数存在します。
- **代表例2：特許第6663066号**（2020年登録：描画用プログラム、描画表現制御装置、制御方法及び記録媒体）
  - **概要**: 描画表現および変形制御に関する比較的新しい特許。

**独自開発で踏んではいけないライン（回避すべき事項）:**
1. Live2D特有の**「ワープデフォーマと回転デフォーマの多段親子構造＋多次元パラメータのキー補間」**というアーキテクチャをそのまま模倣した汎用モデリング／再生システムを自作すること。
2. Live2D Cubismのモデルデータ（`.moc3` / `.cmo3` 等）を独自解析して再生する非公式ランタイムを作ること（利用規約違反および著作権・特許侵害リスク）。

> [!NOTE]
> **Inochi2Dについて**: Inochi2DはBSD 2-ClauseのOSSとして公開されていますが、OSSライセンスは「プログラムの著作権」を許諾するものであり、第三者の「特許権」に対する無侵害を保証するものではありません。Live2Dと類似したメッシュ・パラメータ構造を採用する場合、日本国内での商用展開においては各国の特許範囲との抵触有無に注意が必要です。

### 4.2 特許リスクが極めて低い「安全圏」の技術アプローチ
以下の手法は、CG・ゲーム開発において数十年単位で広く公知となっている標準アルゴリズムであり、独自実装における特許リスクが極めて低い領域です。

1. **2D三角形メッシュ＋ボーン階層（LBS：Linear Blend Skinning）**
   - 3Dゲームで標準的なスケルタルアニメーションを2D平面 `(x, y)` に適用したもの。座標変換行列の線形補間であり、完全に基礎技術。
2. **公開学術論文に基づく変形アルゴリズム（ARAP / Mean Value Coordinates）**
   - Igarashi et al. (*As-Rigid-As-Possible Shape Manipulation*, 2005) や Sorkine & Alexa (*As-Rigid-As-Possible Surface Modeling*, 2007) などの公開論文アルゴリズム。
3. **スプライト切り替え＋2Dシェーダー／アフィン変換演出**
   - 複数枚の絵の切り替え（フレームアニメーション）に、サイン波による頂点揺れ（旗や髪・コートの揺れ）、スケール・回転・スキュー変形、色フラッシュを重ねる手法。

## 5. 独自開発に向けた推奨アーキテクチャ

「既存ソフトに依存せず、低コスト・低リスクで、見栄えの良い2Dイラストのゲームを作る」ための現実的な3つの選択肢を提案します。

### 推奨案A：コマ切り替え（約20枚）＋シェーダー／プロシージャル揺れ（本プロジェクト向け最推奨）
- **構成**:
  - キャラクターの大きな姿勢変化（8方向・攻撃・怯み・ダウン等）は**約20枚のスプライト切り替え**で表現。
  - 静止中や歩行中に「生きている感」を出すため、独自シェーダー（またはCanvasメッシュ分割）で**呼吸の上下伸縮、コートや髪の裾のサイン波揺れ、歩行ボビング、接地影**をリアルタイム加算。
- **メリット**:
  - **特許リスクが事実上ゼロ**。
  - SpineやLive2Dのような複雑なリギング工程が不要（生成AIやイラストレーターが描いた絵をそのまま使える）。
  - 1人称視点で回り込んだときの「背面」「側面」など、ボーン変形だけでは不可能な立体角度を自然に表現できる。

### 推奨案B：2Dボーン＋メッシュスキニングの独自実装（またはMITランタイム活用）
- **構成**:
  - パーツ分けしたPSD/PNGから三角形メッシュを生成し、階層ボーン＋LBS（またはARAP）で動かす軽量ランタイムを自作。
  - もし既存データの編集ツールだけ借りたい場合は、出力JSONがシンプルでランタイムが**MIT License**である **DragonBones** 互換フォーマット等を採用し、ランタイムを自社管理する手もある。
- **メリット**: 関節が滑らかに動くため、少ないイラスト枚数で多様なモーションをプログラム制御（銃口をプレイヤーにリアルタイム追従させる等）しやすい。

### 推奨案C：会話パート等のみLive2D的な立ち絵演出が欲しい場合
- ゲーム本編（戦闘ユニット）は**案Aまたは案B**で完全独自実装しつつ、アドベンチャー／会話パートの立ち絵だけリッチな顔向き表現を使いたい場合は、**Live2D Cubism SDK（年商1,000万円未満の無料枠）** を限定的に使うか、**パーツ差分（目・口・眉の差し替え＋呼吸揺れ＋首の簡易傾き）** を自作するのが最もコスト対効果に優れます。
